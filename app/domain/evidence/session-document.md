# Session document export binding — evidence note (issue #31, child of #5)

## What was added

- `app/domain/src/export.rs`:
  - `SessionDocument` + `DocumentPage`: an optional session-level assembled
    document (media vocabulary `application/pdf` only, SHA-256, byte count
    bounded by `pdf::MAX_DOCUMENT_BYTES`, ordered per-capture page bindings
    with declared pixel dimensions).
  - `ExportSession::document` (default `None`), planner layout of
    `documents/<session>/session.pdf` as a new `ContentKind::Document` file
    (after page files, before recipes; manifest still last), and
    `ExportManifest::document` / `ExportManifestDocument` carrying the
    plan-derived path in `foldscan.export/0.1`.
  - Shared validation (`validate_document_fields`): media vocabulary,
    checksum shape, byte bound, non-empty bindings, exact equality of the
    binding order with the session/manifest page order, and per-page
    dimension bounds (zero and `MAX_DIMENSION_PX`).
- `app/domain/src/executor.rs`: `ContentKind::Document` files materialize
  through the existing staged/flush/read-back/atomic-rename gates, from
  either file-backed or in-memory sources; missing document sources fail in
  the pre-root preflight; the executor refuses source/plan mismatches as
  before. `ExportManifest::from_plan` resolves the document layout path by
  exact per-session expected path, not first-match.
- `app/domain/tests/session_document.rs`: 16 new fixture tests
  (planner layout/order-shape rejections, manifest digest sensitivity and
  legacy-absence compatibility, executor happy path with real
  `export_pdf`-generated bytes, checksum-mismatch rollback, unplanned
  source rejection, cancellation before the document file, stale-binding
  rejection after `reorder`).
- Public re-exports in `app/domain/src/lib.rs`.

## What was verified (software-fixture evidence only)

Commands and results run on `feat/session-document-export` (host: Linux
aarch64, rustc 1.98.0):

- `cargo fmt --check` — clean.
- `cargo clippy --all-targets --locked -- -D warnings` — clean.
- `cargo test --locked` — 181 passed; 0 failed across all suites
  (16 new tests in `tests/session_document.rs`, 165 pre-existing tests
  unchanged and green, including every byte-exact golden/planner/manifest
  digest from earlier slices — the additive optional field changed no
  existing digest).
- Mutation canary: replacing the order-equality guard with `false` fails
  exactly the 4 order-sensitivity tests (planner swap/drop/add, stale
  binding after `reorder`, manifest tamper); restoring it returns 16/16.

## Honesty boundaries

- The exported document payload in the executor test is real
  `pdf::export_pdf` output over synthetic frames; the executor verifies it
  byte-for-byte, but this slice does not parse the finalized PDF back into
  page objects. Page-order proof is at the manifest/binding level (issue
  #5's "verify exported page order/dimensions ... where applicable"), not a
  PDF-content-level verification — that remains the PDF module's own
  self-check plus a future parser slice.
- Only `application/pdf` is accepted; no OCR-text or other document kinds
  exist yet.
- No new dependencies, no network, no UI, no physical device or bench
  measurement is involved in any claim here.
